# Kotoba V2.9 实质性更新提示词

请在当前 Kotoba 仓库实际完成下面的产品更新，修改代码、运行检查并交付可运行结果。

用户已确认 2.8 完成。以最新仓库为基线，简短核查已有功能与必要依赖，不重复开发验证通过的部分。用户报告的完成状态与本次重新验证的结果分别记录。此文件是下一轮开发要求，本身不代表代码已实现。

Kotoba 是我个人使用的英语、日语学习工具，主要在 Android 手机上使用。原有苹果式质感、醒目的学习重点、自然且明显联动的动画继续保留。本轮必须新增实际可用的学习能力，交付重点是：把自己想读的内容变成可阅读、可积累词句、可复习、可听与可跟读的学习材料，再纳入日常学习。

## 一、产品变化与范围

本轮做四项相互关联的能力：

1. 个人学习素材：粘贴或导入文本，保存为可继续学习的文章。
2. 语境词句卡与巩固练习：从文章中积累真实表达，进入已有复习系统。
3. 听力与跟读工作区：句段播放、听力练习、录音回听，保存真实学习结果。
4. 按时间组织的每日任务：结合到期复习、未完成学习和个人素材安排任务。

可验收示例：我粘贴一篇日文短文，标记一个词与一句表达，保存释义后加入复习；第二天能从原文语境复习这张卡，点击来源回到对应段落；文章有可用音频时能循环听一句、隐藏文本听后作答、录制自己的跟读并回听；这些学习结果更新今日任务并在刷新后保留。

四项能力分批实现与验收。保留原内容扩充路线，必要的关联资料继续补充；不以本轮几篇示例取代原总目标。本轮不扩展社交、商城和多人运营功能。优先复用既有工具与服务。

## 二、第一批：个人素材导入与阅读工作区

### 实际操作

1. 在现有资料库增加明确的“导入素材”入口，支持粘贴文本、导入 UTF-8 TXT/Markdown。首轮不承诺网页抓取、PDF/OCR 和图片识别。
2. 导入前可设置标题、语言和可选来源；展示预览。资料可标为“等级未评估”，用户可手动指定等级，不用未经验证的模型结果伪装准确等级。
3. 处理空内容、异常大小、编码失败、重复导入与取消。给出清楚结果；重复内容允许用户明确保留副本，但不静默生成多个重复记录。
4. 生成稳定素材 ID 与段落/句段定位。日语和英语的分段符合各自标点与引用习惯，不把英文缩写或日文引号内容随意切碎。
5. 沿用现有阅读组件，提供文字大小、行距、段落标记、笔记与续读。打开面板、切换页面或刷新后恢复位置。
6. 手机端既支持选中文字，也支持点击句子后操作；不要让精准拖动文本选择成为唯一入口。
7. 保留原文与来源。编辑原文时维护内容版本或旧快照，使既有词句卡能看到原始语境，失效锚点有合理回退。

### 解释与翻译的边界

复用已有可用词典或翻译能力，并清楚标注来源。个人素材中的释义、译文和笔记可由用户补充与编辑；没有对应服务时依然能完成导入、阅读、保存词句与填写释义。不能自动编造词义、译文、语法关联或答案，也不把空按钮当成功能。

### 完成标准

英语、日语分别导入一篇真实测试文本，保存后刷新可打开、继续阅读、编辑与删除。未评估等级不混入审核课程数量；个人素材按用户隔离，已有课程和记录保持兼容。

## 三、第二批：语境词句卡与有效复习

### 从素材生成个人卡片

1. 点击词句后可选择“加入复习”，保存词或表达、语言、语境原句、个人释义、来源素材 ID、内容版本与位置。允许整句卡。
2. 新卡接入现有 SRS 和到期队列，不另建一套复习记录。首次到期规则沿用已有调度设计。
3. 同词不同义可保留不同语境；相同来源与相同内容的重复保存应提示复用。不要仅按词形合并所有义项，更不要改动已有词汇 ID。
4. 复习页支持“看语境回忆表达”和“看表达回忆含义”，翻面后展示原句、释义与来源。按现有调度规则反馈掌握程度。
5. 点击来源能回到对应段落，返回复习后仍停留在同一张卡；原文修改或删除后仍可查看卡片保留的语境快照。
6. 提供编辑、暂停复习与删除个人卡片的入口；与来源文章的删除关系清楚，避免一删文章就隐式丢失全部复习历史。

### 巩固练习

1. 利用已有审核题目按知识点检索相关题，错题复习可换同知识点的另一题；未找到替代题时如实回退。
2. 对个人素材可生成原文遮词回忆：使用用户确认的目标表达与原句，保留原文上下文和来源，并支持翻面自评。
3. 原文填空的其他合理答案不能被当作语言错误；没有可靠变体判断能力时作为原文回忆或自评练习，不制造权威评分。
4. 用户卡片和派生练习与人工审核课程分别统计。AI 生成题目仅在已有真实服务可用时接入，状态与来源明确。
5. 错题按题目/知识点关联保存，保留用户答案和解析。一次操作和同步重试不重复记录，不能用点击答案解析直接判定掌握。

### 完成标准

从一篇个人素材保存词卡和句卡，进入到期复习，作答或自评后更新现有 SRS；来源跳转、文章编辑/删除、刷新恢复、语言切换和离线重试均保持卡片与记录一致。

## 四、第三批：听力与跟读工作区

### 播放与材料

1. 先核查现有音频与朗读能力，复用可用实现。材料区分真人音频、已有生成音频和设备朗读，不把设备声音标成真人录音。
2. 支持播放/暂停、速度调节、当前句段循环和文本显示/隐藏。句段边界来自真实可用信息，不展示编造的音频时间戳。
3. 设备朗读只有验证其可用后才显示可用；网络音频只有实际下载并验证可播放后才显示可离线。缺少语音、音频失效或不支持速度调节时提供准确状态。
4. 如支持用户导入音频，明确“附加音频”与“已有准确句段同步”是不同能力；没有转写/对齐服务时允许手动设置边界或使用整段播放，不能假装自动对齐成功。
5. 处理手机上的用户启动播放、切后台、页面离开、快速切句、播放取消和失败重试；同一时刻不能有多个声音互相覆盖。

### 听力学习

1. 审核课程音频关联已有理解题与解析；个人素材可用隐藏文本后的原句回忆或自评。只有真实答案与评价依据齐全时提供自动判定。
2. 听后可查看正文、答案、解析和相关词句，方便加入复习。
3. 播放时长、听力练习完成和理解正确率分别记录；打开页面或播放完成不等同于掌握。

### 跟读

1. 实现申请麦克风权限、录制、停止、回听、重新录制和删除。拒绝权限或不支持录音时给出具体可恢复状态。
2. 第一阶段采用原音与自己的录音切换回听，必要时显示已有可靠音量/时长信息。没有真实评价服务时不生成发音准确度分数。
3. 默认录音在个人设备保存，明确标记是否仅本机可用。上传、云端保存或外部评分由用户对应操作触发，不自动发送私人录音。
4. 处理连续录制、页面离开、麦克风释放、编码失败与存储不足。录音保存失败不得显示保存成功，也不计入成功完成。
5. 如已有真实语音评价服务，实际验证其语言支持、请求与结果对应、超时及失败处理后再接入；密钥保留在服务端。

### 完成标准

交付英语、日语各至少两个可实际使用的示例听力单元，可复用已有材料；记录文本、音频来源、可用播放方式、题目与答案来源。手机上能完成“播放 → 隐藏文本练习 → 查看解析/原文 → 跟读录音 → 回听 → 保存记录”。真机未测试时明确标记。

## 五、第四批：把新能力纳入每天的学习

1. 支持 5/10/20 分钟任务预算。先用简单透明规则，沿用现有学习引擎，不依赖尚未接入的 AI 调度。
2. 规则优先考虑：到期复习、未完成任务、近期薄弱知识点、已有可用的听力与个人素材。各项已有时复用；不足时说明，不生成虚假任务。
3. 课程预计用时来自内容规则或可靠历史，标注为估计值，不把“20 分钟预算”声称为必定精确耗时。
4. 展示简短推荐原因，例如“昨日未读完，继续第 3 段”“这组表达最近两次回忆困难”。用户可替换素材、跳过或调整时长。
5. 超出预算的到期复习保留积压，不静默推迟 SRS 日期，也不强制用户清空复习才能结束当日学习。
6. 学习中调整预算不丢失已完成步骤；任务只列出设备和数据条件下真正可用的操作。
7. 刷新、跨日和切换语言后正确恢复任务身份。完成记录、卡片复习与播放/录音结果分别统计，避免一次活动被计成多次完成。

完成标准：选择不同时间预算能生成长度不同、有原因、可调整的任务，能连续进入已实现的素材阅读、复习与听力；完成后首页数字与实际记录一致。

## 六、数据与同步是实现的一部分

先检查当前 schema、IndexedDB、同步队列、Auth/RLS、SRS、缓存与恢复机制，确定素材、词句卡、媒体元数据和学习记录的最小落点。尽量复用现有结构，但不能为了维持“零迁移”把本应持久化的功能做成刷新即丢的演示。

确需新字段或表时，设计最小、向后兼容的新增迁移及隔离检查；不修改历史迁移，不清空个人数据。提交可审查 SQL、用途和验证结果。生产执行遵循现有授权与部署流程，不能把计划里的新增能力解释为可以盲目执行生产 SQL。遇到权限阻塞，保存证据并继续本地可做的实现。

文本素材、卡片和学习记录使用稳定身份与幂等写入，遵循现有冲突策略。通过真实跨设备核对后才能标记已验证同步。媒体文件与元数据同步范围分开说明；只同步元数据不代表音频/录音在第二设备可播放。

增加或完善个人学习数据导出与恢复，包含素材、语境卡、必要调度与记录。媒体可用备份包或明确的文件清单说明，缺少媒体时导入应报告缺失，不能声称完整恢复。处理重复导入、冲突、数据版本与不同账户的边界。

## 七、手机界面与交互质量

1. 沿用原统一视觉体系，新功能真正进入首页、阅读与复习流程，不作为互不关联的独立演示页。
2. 阅读正文是视觉中心，解释与加卡面板就近展开；关闭恢复位置。播放器与录音操作固定在合理区域，不遮住文本或软键盘。
3. 主要操作位于拇指容易触及的位置，触控目标约 44px 以上，支持长句、日文与英文混排、文字放大和深色主题。
4. 导入到阅读、选句到加卡、阅读到来源复习、听力到跟读有协调的过渡与反馈；清楚区分处理中、成功、失败与可重试。
5. 避免逐帧更新整个页面、大量模糊与常驻动画。音频/录音资源和监听器及时释放，切页后不持续占用麦克风。
6. 尊重减少动态效果设置，保留键盘访问、面板关闭和可理解的按钮名称。

## 八、验收场景与交付

执行仓库实际存在的 typecheck、lint、tests、content:audit、生产 build。围绕状态恢复、调度、重复写入、账户隔离与媒体生命周期补必要回归测试，避免只验证组件存在。

必须逐项报告以下场景：

| 场景 | 应有结果 |
|---|---|
| 英语/日语文本导入 | 可预览、保存、重新打开与续读 |
| 重复素材与重复加卡 | 按用户选择复用或保留副本，不静默重复写入 |
| 原文修改或删除 | 既有卡片的语境快照和历史保持可用 |
| 卡片复习与来源跳转 | 返回仍是同一张卡，SRS 更新与实际操作一致 |
| 离线文本学习后重连 | 素材、笔记、卡片与学习结果不丢失、不重复 |
| 听力播放与快速切句 | 取消及时，无多个声音叠加，状态真实 |
| 录音权限拒绝/页面离开/存储失败 | 可恢复，释放资源，无虚假保存或完成 |
| 调整每日任务预算 | 已完成进度保留，任务与可用能力匹配 |
| 第二设备 | 同步范围正确，本机媒体不会假装已同步 |
| 数据导出与恢复 | 可恢复约定范围，冲突和缺失媒体有报告 |
| 360/390/430px 与主题 | 无遮挡/溢出，放大文字和减少动态效果可用 |

交付真实代码、运行方法、示例材料、关键截图和核心流程录屏。分别列明本地、真机、线上、跨设备的已验证与未验证事项。更新版本、更新日志、CURRENT-STATUS、内容与能力清单、遗留问题和下一轮断点。交接包哈希按实际文件重新生成。

完成定义：用户能把自己的真实文本保存为学习素材，积累语境词句并复习；能完成实际听力与跟读活动；每日任务能调用这些能力；刷新、离线和同步不破坏记录。功能只有入口或静态界面不算完成，依赖外部服务受阻的部分要明确标注，不能降低完成定义。

## 九、执行方式

先输出简短现状与第一批实施清单，然后直接执行。按“个人素材 → 语境卡与复习 → 听力跟读 → 每日任务整合”逐批提交可验收结果，持续记录状态。普通实现、可逆修改与必要验证自主推进；实际阻塞时提供错误证据和具体恢复点，继续不依赖阻塞的工作。

已有同等能力并验证通过时不要重建，直接补足其真实使用缺口并接入本轮场景。不能只做审计、改版号、页面美化或重复列计划后结束。最终报告必须说明用户现在能新增完成哪些学习操作，并提供验证依据。

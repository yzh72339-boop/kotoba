继续以个人使用、英语与日语、手机优先为目标。你要求的苹果式质感、醒目的主任务、流畅且相互联动的动画，继续作为核心产品要求；保留自由切换语言和等级的能力。

本计划已核对《Kotoba-2.7-Codex-Prompt.md》和《Kotoba-Version-13-Review-and-Plan.md》。前者是开发要求，不能用来证明更新已经实现；后者记录的是 2026-10-08 对 Version 13 源码的审查，不能用来代表今天的仓库。

历史审查记录：667 张词汇卡、67 个完整结构语法专题、14 篇阅读，113 项 Node 测试通过；当时仍存在完整内容覆盖、每日学习入口和状态提示问题。旧资料的结构标准与 2.7 的内容要求也不同，需要重新评定，不能直接算作全部合格。

本次交付的是继续开发的计划与执行提示词，没有修改业务源码，没有运行当前仓库测试，也没有验证生产环境。2.6、2.7 的实际完成情况应由下一轮对最新仓库的核查确定。

## 3. 第一阶段：把 2.7 做到可验收

### 3.1 先确认现状

读取当前仓库的 AGENTS.md、README、CURRENT-STATUS、内容审计、路线图和交接文档，记录当前提交与构建标识。逐项将旧任务标为：已完成且已验证、已完成待验证、部分完成、未完成、受阻。

核查旧审查中的线索：每日学习是否还默认进入旧资料；readiness 是否仍用布尔值混淆错误；语言切换是否残留等级筛选与详情；标签是否写死；内容题目是否存在答案位置规律。问题已修复且验证通过时保留现实现，不为了符合旧描述重新改写。

优先顺序：学习记录与同步正确性 → 核心学习入口 → 首页与阅读等主要界面 → 联动动画 → 全站样式收尾 → 内容首批补齐。

### 3.2 每日学习成为一条真实路线

实现或补全：今日任务 → 到期复习 → 语法 → 相关阅读 → 理解练习 → 完成反馈 → 首页更新。

- 课程选择使用真实语言、等级、前置知识与稳定内容 ID；优先使用合格新资料，真实缺口才回退并说明。
- 首页能直接识别今天学什么、从哪里继续、到期复习还有多少；按钮对应开始、继续或再次学习。
- 会话保存创建时的语言、课程身份、阶段与答题进度。切换语言与等级不改变进行中的会话内容，也不混用统计。
- 阅读保存实际锚点；打开词句解释、进入关联语法、返回阅读后恢复原位置。
- 完成事件与复习记录具备幂等性。重复点击、离线重试、同步重放不重复计数；沿用现有学习与同步机制。
- 部分完成、主动退出、刷新恢复和跨日继续均有明确规则。当天日期依据现有时区约定计算，不无意改动历史统计口径。

### 3.3 视觉与动画同时落实

沿用 2.7 的黑白银灰基础与蓝色强调。若使用已有设计交接包，以其中主参考为准。首页的主任务具有最强视觉权重，辅助入口降低权重，真实数据替换所有示意标签。

统一颜色、字号、行距、间距、表面、圆角、高光、阴影、按钮与图标；覆盖首页、学习、词汇、语法、阅读、资料库、个人页、设置、弹窗和加载/空白/错误状态，同时完善深色主题。

动画验收聚焦五个场景：

| 场景 | 应有行为 |
|---|---|
| 首页进入语法 | 卡片、标题与核心表达在空间上连续，返回恢复原位置 |
| 语法进入阅读 | 关联表达保持识别，阶段与进度同步变化 |
| 点击词句 | 选中、解释面板、遮罩与背景协调变化，关闭恢复阅读锚点 |
| 答题 | 按压、选中、判定、解析、下一题顺序清楚，阻止重复写入 |
| 完成学习 | 完成反馈与首页按钮、数字、进度一致更新 |

允许连续操作与反向过渡，处理快速点击、中途返回与取消，不用长时间锁死操作掩盖状态问题。尊重系统减少动态效果设置。动画优先使用 transform/opacity，控制模糊和持续装饰效果；沿用项目已有技术，不为视觉效果替换框架。

### 3.4 2.7 必须通过的验收

| 验收项 | 通过条件 | 所需证据 |
|---|---|---|
| 完整学习 | 从首页开始到完成结果，课程与统计始终一致 | 流程操作记录与检查结果 |
| 刷新恢复 | 语法、阅读、练习中刷新能继续同一任务 | 各阶段恢复结果 |
| 语言切换 | 筛选与详情有效，原任务保留身份，朗读与统计使用课程语言 | 日语/英语切换结果 |
| 重复操作 | 完成与同步重试不产生重复学习或复习记录 | 必要回归测试与记录 |
| 手机界面 | 360/390/430px 无溢出与遮挡，长标题、放大文字、键盘与安全区域可用 | 截图；真机项目单独标记 |
| 动画 | 连续、可中断、可返回，深色与减少动态效果模式正确 | 核心流程录屏或可复核的动态检查 |
| 工程检查 | 执行仓库已有 typecheck、lint、tests、content:audit、build | 命令、结果与未执行原因 |

工程检查通过不替代真实 owner 写入、手机 PWA、离线重连或第二设备验收。没有环境的项目标记“未验证”，留下具体操作路径，不阻止独立的本地实现继续推进。

## 4. 第二阶段：内容从条目变成课程

### 4.1 两条目标线

第一条是 2.7 已提出的首轮覆盖线：日语 N5–N1、英语 A1–C2，共 11 个等级，每级至少 10 个合格语法专题与 5 篇合格阅读；最低合计 110 个语法与 55 篇阅读，但一个等级的超额不能抵消另一个等级的缺口。

第二条是原完整目标，继续保留：

| 语言 | 等级 | 语法目标 | 阅读目标 |
|---|---|---:|---:|
| 日语 | N5 | 70 | 50 |
| 日语 | N4 | 100 | 60 |
| 日语 | N3 | 150 | 70 |
| 日语 | N2 | 180 | 60 |
| 日语 | N1 | 180 | 50 |
| 英语 | A1 | 60 | 40 |
| 英语 | A2 | 80 | 50 |
| 英语 | B1 | 100 | 60 |
| 英语 | B2 | 120 | 60 |
| 英语 | C1 | 120 | 50 |
| 英语 | C2 | 100 | 40 |
| 合计 | 全部 | 1,260 | 590 |

实际新增量应在最新内容审计后计算。既有合格资料计入，旧简短资料单独报告。原审查中的 1,769 份缺口只代表当时基线。

### 4.2 可持续的补充方法

先补实际空缺等级，并同时加强当前选定学习等级；没有用户新选择时沿用应用保存的等级。每批建议围绕一个主题，约 3–5 个语法专题与 1–2 篇关联阅读，已有内容足够时优先修订和连接。

课程应有前置知识、清楚顺序和明确学习目标。词汇、语法、阅读与练习通过稳定 ID 建立关联；学习过的旧 ID 不随意重命名或删除。

合格语法：含义、接续或结构、至少 4 个自然例句、必要的易错点与近义区别、至少 5 道有解析的练习。合格阅读：完整正文、分段译文、关键词句、关联语法、至少 5 道理解题，长度与难度符合等级。

检查范围包括结构与引用、近似重复、自然表达、难度、答案与解析一致性、干扰项和答案位置分布。若运行时打乱选项，保存稳定选项身份或可靠排列，使刷新、解析与成绩保持一致。

每批产出：新增/修订 ID 清单、按等级合格量、抽查结论、编译与页面验证结果、剩余缺口。审计未达完整目标时保留真实失败结果，不降低检查门槛来制造完成。

词汇继续补充实际搭配、义项区分、例句和语境；保留已有卡片身份与复习记录。每级有 50 张卡片仅代表已有基础覆盖。

## 5. 第三阶段：听力与跟读

先核查已有能力，优先完成真实可用的音频播放、句段循环、速度控制、字幕显示与听后理解题，再加入基础录音和回听。

- 每份音频记录来源、使用条件与对应文本，朗读音频和真人素材清楚区分。沿用现有 schema，只有确实需要持久字段时才设计最小变更。
- 移动端播放由用户操作启动；处理加载失败、暂停、路由离开和恢复。只有已下载且验证可播放的素材才显示可离线。
- 听力任务与课程内容和学习记录关联；下载失败或仅打开页面不算完成。
- 跟读先实现录音权限说明、录制、停止、回听和删除；录音默认保存在适合当前产品的个人范围内。
- 自动语音识别或发音评价依赖实际接入的服务。没有真实评价能力时提供跟读与回听，不展示虚构评分。

完成标准：Android 上能完成一段音频的学习、理解练习与录音回听；拒绝权限、来电或页面切换等中断后状态合理，记录不丢失。

## 6. 第四阶段：AI 辅导与自适应

### 6.1 先做与现有学习直接相关的 AI

第一批做“解释当前词句”“根据本课生成补充练习”“批改短文”；之后再做带长期上下文的对话辅导。已有 AI 功能存在时先修复和验证，不重复实现。

请求通过现有服务端路径发送，密钥不进入客户端。课程上下文、用户提交内容与必要历史按需提供；完整私人笔记和历史不自动作为所有请求的输入。

实现使用量限制、超时、取消、失败重试和清楚状态。一次用户操作对应一个可跟踪请求，重试不重复保存反馈。缓存与历史按用户隔离；身份与访问控制沿用现有体系。

AI 反馈要能对应原文：指出具体词句、给出理由和可采用的修改。临时 AI 练习与人工审核课程分别统计，不能自动混入合格内容数量。

完成标准：真实服务有成功响应与失败处理证据，费用或使用量可查看；服务不可用时仍能使用已有课程。未接入服务的按钮不伪装成已经完成的功能。

### 6.2 自适应先采用可解释规则

根据到期复习、近期正确率、遗忘记录、未完成任务和用户每日时长调整计划。到期复习优先，弱项获得补充练习，达到用户时间预算后减少新任务。

推荐说明具体原因，例如“最近两次该结构出错，今天追加两题”。用户可调整或跳过。不要用一次错误自动降级，也不把点击次数或使用时长直接当成掌握程度。

洞察只显示有证据的指标：复习积压、最近准确率、真实完成量、薄弱结构与学习连续性。数据不足时明确展示不足，不填充装饰性分数。

## 7. 数据、同步与发布要求

2.7 的 UI 与内容工作沿用现有 Auth/RLS、SRS、IndexedDB、缓存、同步队列、收藏和笔记机制；不为视觉或 JSON 扩充新增数据库迁移。旧文档中的 010 状态先查真实证据或现有只读验证，不重复运行生产 SQL。

后续新能力若需要持久数据，先证明现有结构不足，再设计独立、最小、向后兼容的变更，保持旧记录可用；不修改历史迁移，不把“可以设计迁移”理解为可以未经核查直接执行生产 SQL。

离线验收：下载课程 → 断网学习 → 保存进度/笔记 → 恢复网络 → 同步 → 刷新 → 第二设备核对。验证账户隔离、重复同步、冲突处理和退出登录后的可见数据。先确认现有冲突策略，再补缺口，不盲目另建同步系统。

PWA 更新保留 IndexedDB 与学习数据，继续保留恢复入口。记录发布提交、构建标识和变更；故障恢复依据真实部署能力执行。跨设备和真机验证必须保留实际证据。

RC 最低条件：核心学习无已知阻断问题；课程覆盖达到首轮线；失败状态与恢复入口清楚；离线与同步不丢记录；移动端、主题、减少动态效果与文字放大可用；所有验收分别标记本地、真机、线上或未验证。
